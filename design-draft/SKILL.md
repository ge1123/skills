# 需求轉設計稿

將需求轉成可檢視、可修改的靜態視覺稿。適用於網站、手機 App、桌面軟體等介面，也適用於海報、資訊圖與簡報單頁構圖；不預設成品必須是網站。

## 確認設計目標

沿用使用者已提供的內容、參考、品牌與偏好。當用途、尺寸、主要內容或視覺方向的缺漏會實質影響設計，而且無法合理推定時，集中詢問關鍵項目；資訊足夠則直接製作。使用者若明確要求先詢問，先完成需求確認再開始。

選擇畫板尺寸、資訊密度與展示方式時，以實際用途為準。不要把範例的品牌、產業、深色風格或桌面尺寸帶入其他任務。沒有實際資料時使用前後一致的示意內容，並標示其為示意。

## 產品還原與實作交接

當設計稿用來還原產品或交給他人實作時，把每個畫面的行為規格直接寫在對應畫面區塊，與畫面一起交付。單純視覺提案、海報與簡報可略過此節。用靜態分鏡、文字或表格描述互動即可。

- 各畫面區塊就地說明操作、畫面回饋與資料變化；唯讀或外觀畫面可只說明相關狀態。將失敗、離開和待確認事項放在受影響的區塊。跨畫面驗收另列，案例連回涉及的區塊，區塊也連到相關案例，避免在兩處維護同一份規則。
- 從使用者要完成的任務串起畫面。對每個關鍵轉折寫明起始條件、觸發動作、畫面回饋及資料結果；依任務涵蓋等待、失敗、重試、離開與重新開啟。拖曳、焦點或手機返回等難從單張圖判讀的操作，用前後畫面標註。
- 同一筆資料跨功能時，說清楚可見性、關聯與復原規則。已有 API 或 schema 時，連到相關畫面、端點及資料欄位；用具體輸入、成功或失敗回應和操作後的狀態說明其對使用者的影響。
- 對影響實作的規則註明依據，區分原版實測、文件記載、設計決策與待確認事項。若資料只足以證明存在更新端點，就把儲存時機列為待確認。新產品可提出預設行為；還原案要保留未知之處。
- 用固定示例資料為核心流程寫可重現的驗收案例，包含前置狀態、步驟、可觀察結果，以及涉及持久化時重開後的結果。例如用同一筆記驗收「編輯後立即切換，再回來」和「儲存失敗後重試」，分別寫出正文、儲存提示及最後保存的內容。待確認的預期結果標示為未定，已撰寫與已實測的案例分開標記。
- 交付前從實作者角度走讀案例：只用稿內資訊，能否判定每一步該顯示什麼、資料如何變化、何時算通過？將無法判定且影響核心任務的問題集中列在對應流程旁。

## 選擇製作方式

先遵循使用者指定的技術與交付格式。還原既有產品時，在符合這些要求的前提下，優先沿用可取得的元件與樣式。從零製作且未指定技術時，再依下表選擇預設方案。

採用 TSX 時，用它組織與重用元件；HTML、CSS 與 SVG 則依內容需要搭配。

| 任務重點 | 優先方式 | 需讀取的參考 |
| --- | --- | --- |
| 固定尺寸的介面、海報、資訊圖或單頁構圖，先看視覺方向 | 預設 TSX＋SVG | [固定畫板](references/fixed-canvas.md) |
| 長文字、表格、內容會增減，或要檢查不同尺寸的重排與換行 | TSX＋HTML＋CSS，圖形按需用 SVG | [流動排版](references/flow-layout.md) |
| 同時包含內容排版與精確圖形 | 依主體選一條路線，局部混合；只有遇到另一類問題時才讀另一份參考 | 上述適用的一份 |
| 使用者指定可編輯的 PDF、PPTX 等成品格式 | 以交付格式選工具，必要時使用環境中對應的成品技能 | 不強制經過瀏覽器或 SVG |

只讀取本次需要的參考。

在滿足視覺與修改需求的前提下，選擇最少必要結構與依賴。不要只靠原稿字元數推論 token、模型準確性或製作速度；也不為縮短程式碼而犧牲清楚的結構與可讀性。

## 製作與檢查

- 先建立版面與閱讀順序，再統一字級、間距、色彩、圖形與元件；用共用參數保持一致，避免把每個細節都變成通用元件。
- 以靜態稿為範圍，表現必要的內容與狀態。只有使用者要求時才加入產品互動、真實登入或資料服務；白板的平移與縮放屬於檢視工具。
- 在本次目標尺寸實際渲染並檢視畫面，修正溢出、重疊、截斷、字型替換與層級不清。需要多尺寸排版時才增加相關尺寸檢查。
- 若有指定成品格式，檢視實際匯出結果；不能只憑原始碼或成功建置宣稱版面正確。環境無法渲染時，明確說明尚未驗證的部分。

## 展示與交付

交付可編輯原稿與可直接檢視的預覽。需要啟動環境時，附上最少必要的執行方式；已有可用環境則沿用。

多張稿優先放在同一白板或並排總覽，保留名稱與原始尺寸，方便放大、比較與討論；單張稿直接展示即可。白板是承載設計的工具，不改變稿件本身的用途。不同稿件的樣式與識別碼應隔離，避免共用檢視頁互相干擾。

使用者要求版本比較時，以相同目標尺寸重新截圖並清楚標示版本；保留實際高度差異，避免拉伸或裁切掩蓋差異。PNG 可用於預覽與比較，但不能取代約定的可編輯設計原稿。

摘要說明採用的方式、設計重點與檢查結果，提供原稿與預覽連結。修改既有稿時聚焦指定範圍，保留有用的版本與參考，不反覆輸出整份程式碼。
